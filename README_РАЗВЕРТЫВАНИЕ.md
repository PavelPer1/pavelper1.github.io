# ЛААМА — демонстрация пяти дизайнов

Это готовый **статический сайт-превью** для показа клиенту. В левой панели есть только логотип и пять переключателей: «Дизайн -1» — «Дизайн -5». Вспомогательные пояснения, палитры и названия концепций в левой панели удалены.

## Быстрый запуск

1. Распакуйте ZIP в отдельную папку на компьютере.
2. Откройте `index.html` в браузере. Подключение к интернету не нужно для картинок и логотипа.
3. На хостинг загрузите **всё содержимое** папки (не только `index.html`), сохранив структуру каталогов.
4. Откройте адрес вашего домена: `https://ваш-домен.ru/`.

Не нужны PHP, Node.js, база данных, npm или процесс сборки. Достаточно любого статического хостинга с поддержкой HTML, CSS, JS.

## Файлы

```
index.html          ← страница с переключателем вариантов (открывать её)
design-1.html       ← вариант №1
design-2.html       ← вариант №2
design-3.html       ← вариант №3
design-4.html       ← вариант №4
design-5.html       ← вариант №5
css/preview.css     ← стили панели просмотра
css/site.css        ← общие стили всех макетов
js/app.js           ← логика переключателя дизайнов
assets/logo.png     ← предоставленный логотип
assets/sofa-*.webp  ← временные изображения диванов
```

## Публикация на обычном хостинге (Beget, Timeweb, REG.RU, cPanel/ISPmanager)

1. Создайте сайт или поддомен, например `demo.example.ru`.
2. В файловом менеджере откройте **корневую директорию сайта**. Она может называться `public_html`, `www`, `htdocs` или иметь другое имя, указанное в панели хостинга.
3. Закачайте содержимое архива: `index.html`, `design-1.html` — `design-5.html` и каталоги `assets`, `css`, `js`.
4. Убедитесь, что `index.html` находится непосредственно в корне сайта, **не внутри дополнительной папки** `LAAMA_client_hosting`.
5. Откройте свой адрес и поочередно проверьте пять вариантов, фотографии и кнопки смены разрешения.
6. Если домен подключен, включите HTTPS/SSL в панели хостинга (обычно сертификат Let's Encrypt).

### Если используется VPS с Nginx

Разместите содержимое архива в директории, на которую указывает `root` вашего виртуального хоста. Пример блока:

```nginx
server {
    listen 80;
    server_name demo.example.ru;
    root /var/www/laama-demo;
    index index.html;
    location / { try_files $uri $uri/ =404; }
}
```

Этот пример только для HTTP; для реального домена настройте HTTPS и DNS в соответствии с панелью управления.

### Если используется GitHub Pages

Создайте репозиторий, загрузите содержимое архива **в корень репозитория**, затем в Settings → Pages выберите «Deploy from a branch», `main`, `/ (root)` и сохраните. Ссылка будет вида `https://имя.github.io/репозиторий/`. Все пути в проекте относительные, поэтому вложенная папка поддерживается.

## Как менять проект

- Надписи кнопок: `js/app.js`, массив `designs`.
- Стили панели: `css/preview.css`.
- Стили макетов: `css/site.css`.
- Содержимое каждого макета: `design-1.html` — `design-5.html`.
- Логотип: замените `assets/logo.png` файлом с тем же именем.
- Картинки диванов: замените `assets/sofa-01.webp` и другие на собственные WebP-файлы тех же имён (или измените ссылки в HTML).

## Важное замечание для заказчика

Демонстрация **показывает варианты внешнего оформления**, но не является рабочим интернет-магазином. Макеты содержат существующие ссылки на `laama24.ru`: переход по ним может вывести пользователя из демонстрации на действующий сайт. Изображения диванов созданы для визуализации и **не показывают фактическую продукцию ЛААМА**. Перед интеграцией в официальный магазин их нужно заменить реальными фотографиями товара и дополнительно проверить функциональность страниц.

Шрифты могут загружаться из Google Fonts при доступном подключении. Если этот сервис недоступен, автоматически применяются системные запасные шрифты. Для локального хранения шрифтов необходимы соответствующие файлы и соблюдение условий их лицензий.

### Неиндексация и приватность

В `index.html` установлен `robots=noindex,nofollow`, однако **это не защита паролем**: любой обладатель ссылки сможет открыть дизайн. Для ограничения доступа включите пароль к директории через панель хостинга или HTTP Basic Auth. Перед отправкой заказчику проверьте адрес в приватном окне браузера.
